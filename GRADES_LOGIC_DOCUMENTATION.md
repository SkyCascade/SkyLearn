# 📚 Документация: Логика выставления оценок в TeacherGradesPage

## 🎯 Цель системы

Система выставления оценок позволяет преподавателям управлять оценками студентов для своих курсов с автоматическим расчетом итоговых баллов и буквенных оценок.

---

## 📊 Структура оценок

### Компоненты оценки (100 баллов максимум):

| Компонент | Максимум | Описание |
|-----------|----------|----------|
| **Attendance** (Посещаемость) | 30 баллов | Оценка за посещение занятий |
| **Activities** (Активность) | 30 баллов | Оценка за активность на занятиях, домашние задания |
| **Exam** (Экзамен) | 40 баллов | Итоговый экзамен |
| **Total** (Итого) | 100 баллов | Автоматически рассчитывается: attendance + activities + exam |

### Периоды оценивания:

1. **1st Module** (1-й модуль) - первая половина семестра
2. **2nd Module** (2-й модуль) - вторая половина семестра  
3. **Semester** (Семестр) - итоговая оценка за весь семестр

## 🔄 Логика работы системы

### 1. Загрузка данных (при открытии страницы)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Получить информацию о allocation (курс + группа)         │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ 2. Загрузить ВСЕХ студентов группы из API                  │
│    GET accounts/api/groups/{group_name}/students            │
│    ✅ Показываются ВСЕ студенты, даже новые без оценок      │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ 3. Загрузить существующие оценки для курса                 │
│    GET result/api/grade-{module}/?course={courseId}         │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ 4. Объединить студентов с оценками (mergeStudentsWithGrades)│
│    - Для студентов с оценками → показать их оценки          │
│    - Для новых студентов → показать нули (0, 0, 0)          │
└─────────────────────────────────────────────────────────────┘
```

**КЛЮЧЕВОЕ ИЗМЕНЕНИЕ:** 
Раньше загружались только студенты, у которых есть оценки. Теперь загружаются **ВСЕ** студенты группы, независимо от наличия оценок.

### 3. Изменение оценок (handleGradeChange)

Когда преподаватель вводит оценку в поле:

```javascript
handleGradeChange(studentId, field, value)
  ↓
1. Конвертировать value в число (пустая строка → 0)
  ↓
2. Найти запись оценки студента в массиве grades
  ↓
3. Обновить поле (attendance/activities/exam)
  ↓
4. Пересчитать Total автоматически
  ↓
5. Обновить состояние grades (React state)
```

**Пример:**
```javascript
// Студент вводит 25 в поле Attendance
handleGradeChange(123, 'attendance', '25')

// Результат:
{
  student: 123,
  course: 456,
  attendance: 25,    // ← обновлено
  activities: 30,    // старое значение
  exam: 40,          // старое значение
  total: 95          // ← пересчитано: 25 + 30 + 40
}
```

---

### 4. Валидация оценок (validateGradesBeforeSave)

Перед сохранением проверяются:

✅ **Диапазоны значений:**
- Attendance: 0-30
- Activities: 0-30
- Exam: 0-40
- Total: 0-100 (автоматически)

❌ **Ошибки при валидации:**
```
❌ "Иван Иванов: Attendance must be between 0-30"
❌ "Петр Петров: Exam must be between 0-40"
❌ "Сидоров С.: Total score cannot exceed 100%"
```

## 🔑 Backend: get_or_create логика (result/views.py)

### Что происходит на бэкенде при сохранении:

```python
# Для каждого студента в bulk-update запросе:
for grade_data in request.data['grades']:
    student_id = grade_data['student_id']
    
    # Попытка найти или создать запись
    grade_obj, created = model.objects.get_or_create(
        lecturer=request.user,
        course_id=course_id,
        student_id=student_id,
        defaults={
            'attendance': 0,
            'activities': 0,
            'exam': 0,
            'total': 0,
        }
    )
    
    # Обновление значений
    grade_obj.attendance = grade_data['attendance']
    grade_obj.activities = grade_data['activities']
    grade_obj.exam = grade_data['exam']
    grade_obj.total = attendance + activities + exam
    grade_obj.save()
```

**Результат:**
- ✅ Если запись существует → обновляется
- ✅ Если записи нет (новый студент) → создается с нулями, затем обновляется

## 📈 Система буквенных оценок (Letter Grades)

### Конвертация Total → Letter Grade:

| Total баллы | Буквенная оценка | Цвет      |
|-------------|------------------|-----------|
| 90-100      | A+               | 🟢 Зелёный|
| 85-89       | A                | 🟢 Зелёный|
| 80-84       | A-               | 🔵 Синий  |
| 75-79       | B+               | 🔵 Синий  |
| 70-74       | B                | 🟡 Жёлтый |
| 65-69       | B-               | 🟡 Жёлтый |
| 60-64       | C+               | 🟠 Оранжевый|
| 55-59       | C                | 🟠 Оранжевый|
| 50-54       | C-               | ⚪ Серый  |
| 45-49       | D                | ⚪ Серый  |
| 0-44        | F                | 🔴 Красный|

```javascript
const calculateLetterGrade = (total) => {
  if (total >= 90) return 'A+';
  if (total >= 85) return 'A';
  if (total >= 80) return 'A-';
  if (total >= 75) return 'B+';
  if (total >= 70) return 'B';
  if (total >= 65) return 'B-';
  if (total >= 60) return 'C+';
  if (total >= 55) return 'C';
  if (total >= 50) return 'C-';
  if (total >= 45) return 'D';
  return 'F';
};
```

## 🔧 Ключевые функции компонента

### 1. `loadGrades(alloc, moduleType)`
- Загружает всех студентов группы
- Загружает существующие оценки для курса
- Объединяет данные (merge)

### 2. `loadStudentsFromGroup(groupName)`
- **API:** `GET accounts/api/groups/{groupName}/students`
- Возвращает список всех студентов группы
- **Важно:** Вызывается ПЕРВЫМ, загружает всех студентов

### 3. `mergeStudentsWithGrades(studentsList, gradesData, courseId)`
- Принимает список студентов и список оценок
- Для каждого студента:
  - Если есть оценка → использует её
  - Если нет оценки → создает пустую (0, 0, 0, 0)
- Обновляет state `grades`

### 4. `handleGradeChange(studentId, field, value)`
- Обрабатывает изменения в полях ввода
- Конвертирует значения в числа
- Автоматически пересчитывает Total

### 5. `validateGradesBeforeSave()`
- Проверяет диапазоны значений
- Возвращает массив ошибок (если есть)

### 6. `saveGrades()`
- Валидирует оценки
- Отправляет bulk update на backend
- Показывает результат пользователю
- Перезагружает данные

## 🆕 Исправленная проблема: Новые студенты не отображались

### ❌ Старое поведение (НЕПРАВИЛЬНО):

```javascript
// Загружались только студенты, у которых есть оценки
if (gradesData.length > 0) {
  loadStudentsFromGrades(gradesData);  // Только студенты с оценками
} else {
  loadStudentsFromGroup(groupName);    // Все студенты, только если оценок нет
}
```

**Проблема:**
- Если у 2 студентов есть оценки → показываются только эти 2
- Новый 3-й студент не имеет оценок → не показывается ❌

### ✅ Новое поведение (ПРАВИЛЬНО):

```javascript
// ВСЕГДА загружаем ВСЕХ студентов группы
const studentsList = await loadStudentsFromGroup(groupName);

// ПОТОМ загружаем оценки
const gradesData = await api.get(endpoint);

// Объединяем: для всех студентов создаем оценки
mergeStudentsWithGrades(studentsList, gradesData, courseId);
```

**Результат:**
- Загружаются ВСЕ студенты группы (3 студента) ✅
- У 2 студентов есть оценки → показываются их оценки ✅
- У 3-го студента нет оценок → показываются нули (0, 0, 0) ✅
- Преподаватель может выставить оценки всем ✅

## 🚀 API Endpoints

### Frontend → Backend взаимодействие:

```
1. Получить студентов группы:
```

## 🎓 Заключение

### Ключевые принципы системы:

1. **Полнота данных**: Показывать ВСЕХ студентов группы, не только тех, у кого есть оценки
2. **Автоматизация**: Total и Letter Grade рассчитываются автоматически
3. **Валидация**: Проверка диапазонов значений перед сохранением
4. **Bulk операции**: Все оценки сохраняются одним запросом (эффективность)
5. **get_or_create**: Backend создает записи для новых студентов автоматически
6. **Независимость модулей**: Оценки 1st, 2nd module и semester хранятся отдельно

### Преимущества текущего решения:

✅ Простота: Преподавателю не нужно "добавлять" студентов - они уже есть  
✅ Надёжность: get_or_create гарантирует создание записей при необходимости  
✅ Производительность: Bulk update вместо N отдельных запросов  
✅ UX: Автоматический расчёт Total и Grade  
✅ Валидация: Предотвращение некорректных данных
