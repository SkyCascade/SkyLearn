# 🔍 Анализ проблемы: Почему один запрос возвращал 401, а другой 404?

## ❓ Вопрос

```
Unauthorized: /result/api/lecturer/bulk-grades/bulk-update/
WARNING 2025-10-30 02:27:44,829 log 20157 6190231552 Unauthorized: /result/api/lecturer/bulk-grades/bulk-update/
[30/Oct/2025 02:27:44] "POST /result/api/lecturer/bulk-grades/bulk-update/ HTTP/1.1" 401 58

Not Found: /result/api/lecturer/bulk-grades/bulk-update/
WARNING 2025-10-30 02:27:53,871 log 20157 6190231552 Not Found: /result/api/lecturer/bulk-grades/bulk-update/
[30/Oct/2025 02:27:53] "POST /result/api/lecturer/bulk-grades/bulk-update/ HTTP/1.1" 404 59
```

Почему один запрос возвращает 401, а другой 404?

## 🎯 Ответ

### Причина №1: Два запущенных процесса Django

В системе одновременно работало **два процесса** Django сервера:

```bash
ps aux | grep "manage.py runserver"
adminbaike  20157  ... /venv/bin/python manage.py runserver  # 🔴 Старый (8:25AM)
adminbaike   8349  ... python manage.py runserver             # 🆕 Новый (11:16AM)
```

**Старый процесс (PID 20157)**:

- Запущен в 8:25 AM
- Использует **старую версию кода** БЕЗ исправления (`url_path='bulk-update'`)
- Порт 8000 уже занят → новый сервер не может запуститься
- Возвращает **404** для `/result/api/lecturer/bulk-grades/bulk-update/`

**Новый процесс (PID 8349)**:

- Попытка запуска в 11:16 AM после внесения изменений
- Не может запуститься из-за занятого порта
- Сразу завершается с ошибкой "That port is already in use"

### Причина №2: Python bytecode кеш

Python компилирует `.py` файлы в `.pyc` (bytecode) для ускорения загрузки. Даже после изменения исходного кода, старый скомпилированный файл может использоваться до перезапуска:

```
result/__pycache__/views.cpython-311.pyc  # Старая скомпилированная версия
```

### Причина №3: Django auto-reloader не сработал

Django's `StatReloader` отслеживает изменения файлов, но:

- Если файл изменен **до запуска** сервера - изменения не подхватываются
- Если файл изменен когда работает **старый** процесс - он не перезагружает код
- Нужен **полный перезапуск** для гарантированного применения изменений

## ✅ Решение

### 1. Остановили все процессы Django

```bash
pkill -f "manage.py runserver"
```

### 2. Очистили Python bytecode кеш

```bash
find result -name "*.pyc" -delete
find result/__pycache__ -type f -delete
```

### 3. Перезапустили сервер

```bash
python manage.py runserver
```

### 4. Проверили работу

```bash
curl -X POST http://localhost:8000/result/api/lecturer/bulk-grades/bulk-update/
```

**Результат:**

```json
{"detail":"Authentication credentials were not provided."}
HTTP Status: 401  ✅
```

🎉 **Теперь возвращает 401 (не 404)!**

## 📊 Сравнение HTTP статусов

| Статус               | Значение                                              | Причина                           |
| -------------------- | ----------------------------------------------------- | --------------------------------- |
| **401 Unauthorized** | ✅ Endpoint **существует**, но требует аутентификацию | Backend работает правильно        |
| **404 Not Found**    | ❌ Endpoint **не найден** в URL routing               | Старая версия кода без `url_path` |

## 📝 Итог

### Почему возвращались разные коды?

1. **401** - запросы к серверу с **новым кодом** (после исправления, когда сервер перезапущен)
2. **404** - запросы к серверу со **старым кодом** (до исправления или когда работал старый процесс)

### Настоящая проблема

Не было проблемы с кодом или фронтендом. Проблема была в том, что:

- Запущен был **старый процесс** Django сервера
- Python использовал **скомпилированный кеш** (.pyc файлы)
- Изменения в коде **не применялись** до полного перезапуска

## 🛠️ Рекомендации на будущее

### 1. Всегда проверяйте запущенные процессы

```bash
ps aux | grep "manage.py runserver"
```

### 2. Убивайте старые процессы перед запуском

```bash
pkill -f "manage.py runserver"
python manage.py runserver
```

### 3. Очищайте Python кеш при проблемах

```bash
find . -type d -name "__pycache__" -exec rm -r {} +
find . -name "*.pyc" -delete
```

### 4. Используйте автоматический restart

В production используйте:

- **gunicorn** с `--reload` (development)
- **uwsgi** с `py-autoreload` (development)
- **systemd** для управления процессами (production)

### 5. Мониторьте логи сервера

Обращайте внимание на **PID** в логах - если он не меняется, значит сервер не перезапустился:

```
log 20157 ...  # 🔴 Тот же PID = старый процесс
log 24248 ...  # 🆕 Новый PID = новый процесс
```
